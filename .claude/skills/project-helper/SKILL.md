## 2. Два remote — не перепутать

- `origin` — `https://github.com/Хозяин/zerocode_project_dzen.git` — основной репозиторий, ветка `master`.
- `demo` — `https://github.com/Хозяин/zerocode_project_dzen_final_project.git` — демо-версия проекта для учебного финального проекта, ветка `main`.

Важное: histories `origin/master` и `demo/main` расходились, это разные ветки одного проекта, а не два зеркала. Пушить только по прямому запросу и только в названный remote. Пример точечной доставки файлов в `demo/main` без затрагивания локального `master` — временный индекс: `GIT_INDEX_FILE` + `git read-tree refs/remotes/demo/main` + `git add <путь>` + `git write-tree` + `git commit-tree -p refs/remotes/demo/main` + `git push demo <sha>:main` (после — убрать временный файл индекса).

## 3. Запуск сервиса (ComfyUI)

ComfyUI — единственный сервис проекта: он генерирует картинки статей. Локальная раскладка: запускной Python — `C:\ComfyUI\App\python_embeded\python.exe`, сервер — подпапка `ComfyUI` рядом. Каноническая команда запуска (исполнять в фоне):

```
cd C:/ComfyUI/App
./python_embeded/python.exe -s ComfyUI/main.py --port 8188 > ComfyUI/user/comfyui_session.log 2>&1
```

Правила, которые нельзя нарушать:
- Вывод обязан уходить в файл (`> ... 2>&1`). Пайп типа `| head` обрушит прогресс-бар с ошибкой и сломает генерации.
- Не запускать ComfyUI через comfy-cli — тот тянет системный Python без нужных пакетов.
- Проверка готовности: `curl http://127.0.0.1:8188/system_stats` (JSON появился — сервер жив; первые 30–60 секунд ожидания — норма). Проверка без запуска — тем же curl: пустой ответ означает, что сервер спит.
- Перед тяжёлой генерацией сверять модель: чекпойнт `RealVisXL_V5.0_fp16.safetensors` должен присутствовать в списке чекпойнтов.
- Если порт 8188 занят чужим процессом — не убивать его молча: показать процесс Хозяину и спросить.

## 4. Внесение изменений

Порядок работы всегда такой:
1. Прочитать `CLAUDE.md` и, если меняешь статьи, — скилл `dzen-viral-writer/SKILL.md` целиком.
2. Найти правый файл по карте из раздела 1. Правила нейминга файлов: `[дата (опц.)] — [тема] — [тип].md`, дефисы вместо пробелов, единообразие. Имя папки статьи = имя файла статьи без расширения.
3. Вносить изменение точечно. Архитектуру и структуру папок не перестраивать без объяснения причин — а значит, без предварительного объяснения Хозяину.
4. Ничего не удалять без прямого запроса. «Переименовать» = создать новое + спросить об удалении старого.

Запреты, за которыми следить особенно:
- Правки файлов в `.claude/skills/` и `.claude/agents/` — только по явному запросу Хозяина; любую правку сначала показать точным текстом (старый → новый) и дождаться «да».
- Новые статьи — только через конвейер скилла `dzen-viral-writer`, не руками.
- `.tmp/`, `toDo/` и служебные кэши в коммиты не отправлять.

## 5. Проверка ошибок

- Проверка статьи (объём тела 4000–6000 знаков, сверка с `length:`, длина пути до 260 символов, шаблон имени файла под Windows):
  ```
  python ".claude\skills\dzen-viral-writer\scripts\check_article.py" "дзэн статьи\<папка>\<файл>.md"
  ```
- Скрипт-верdict «Чисто — сохранение по правилам» — обязательное условие перед коммитом статьи.
- Кириллические пути в питон-скриптах: запускать с `PYTHONUTF8=1`; для `python_embeded` — обязательно.
- Текстовые ошибки статей (грамматика, AI-слоп, канцелярит, честность фактов) ловятся вручную по `references/QC-checklist.md` и `references/ai-slop-patterns.md` скилла `dzen-viral-writer`.
- Типовые проблемы окружения (WebFetch блокируется, ComfyUI не отвечает, имя файла не прошло проверку) — таблица решений в разделе 10 файла `Запуск-проекта — инструкция.md`. Оттуда же: если WebFetch отдает «Unable to verify if domain is safe» — обход `curl -sL -A "Mozilla/5.0" <url> -o файл` и разбор HTML маленьким скриптом Python; источник в таком случае пометить в служебном разделе статьи.
- Проверить всю цепочку на живых фактах, а не по памяти: цифры источников — перечитыванием источников целиком; запуски — реальным выводом скриптов, а не ожиданиями.

## 7. Подготовка к публикации

Публикация — две разные вещи, не смешивать.

**Публикация в Git (конец рабочего блока):**
1. Собрать состояние: `git status --short` + `git diff --stat` — показать Хозяину, что именно уйдёт.
2. Коммитить только после явного «да» от Хозяина. Сообщение коммита — на русском, по существу, в конце строки `Co-Authored-By: Claude Code <noreply@anthropic.com>`.
3. Пуш `origin master` для основного репозитория; `demo` — только по отдельному запросу и только в `main`.
4. Перед пушем статьи проверить: папка статьи целиком (`.md` + выбранные PNG) отслеживается, имя файла прошло `check_article.py`, путь не длиннее 260 символов.

**Публикация статьи в Дзен (руками, вне репозитория):**
1. Открыть `dzen.ru/editor` через Яндекс ID → «Создать публикацию» → «Статья».
2. Заголовок до 56 символов с главным ключевым словом.
3. Обложка 1080×608 (из папки статьи; сгенерированная 1344×768 кропается до 1080×608, например PIL по центру).
4. Текст из `.md` без служебного раздела; картинки — примерно по одной на 3–4 абзаца.
5. Описание до 160 символов — для поиска Яндекса.
6. Нажать «Опубликовать»; модерация обычно 10–30 минут.
7. После 24 часов от публикации статью не править: алгоритм тестирует её на выборках, частые правки сбивают процесс.
